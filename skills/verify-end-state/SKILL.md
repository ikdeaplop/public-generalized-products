# 终态回读护栏

## 何时触发本技能
- 刚做完：写文件、部署、上传、启动服务、导入配置、跨机投递，准备说「成功了」。
- 眼前判据是：退出码 0、接口返回 200、错误号 0、同步完成度 100%、进程存在、配置显示「已启用 / 已绑定」、定时任务状态 0。
- 这些信号**只证明「动作发出了」，不证明「结果对了」**——它们是过程信号，不是终态实证。

## 核心规则：宣布成功前必须回读终态
按场景选对应回读动作（不能只看「没报错」）：
- **写文件**：用列表 / 检索实证文件存在、非空、内容正确；工具静默丢弃字段时，靠正面产出旁证（截图、接口返回）确认。
- **上传 / 同步**：查**接收方**是否真拿到（同步工具用数据库浏览接口或对方列目录；同步完成度 100% 只是发送方口径，「投递成功不等于对方收到」）。
- **启动应用 / 服务**：用权威判据（苹果系统用授权校验结果而非进程查询；用启动命令加进程查询会误判单实例应用已启动）。
- **密钥 / 配置导入**：查「能否真用」（能否解密 / 能否真调通），而非插入 / 写入成功；解密逻辑「先环境变量后数据库」时，孤儿子密钥会悄无声息用错。
- **断连 / 离线**：先判**整机是否开机**（系统运行时长 / 最近连接时间戳），再查进程半死；远程判离线先怀疑电源。
- **连接器 / 通道**：先查配置文件里有无该服务条目（本机压根没装不等于配在别实例）；「已启用」不等于「当前会话能用」（还差实例维度）。

## 两个元规则（最贵的两类坑）
1. **诊断未闭环前不落定论**：线索没收敛就先标「疑似 / 待复测」，别写成铁律——连续多天推翻自己结论的坑代价最高（曾出现第 3 天订正推翻前 2 天结论）。
2. **通道异常别谎报成功**：产出落「待推送 / 待处理」目录、标状态，恢复后一键补；绝不说「已推送 / 已完成」。

## 关联根因族（半夜复盘体系）
- G1 静默失败·状态不等于结果（跨 10+ 子系统，最致命）
- G3 并发写回滚 / 诊断未闭环
- G4 局部状态不等于全局状态

## 用法建议
动手前把本技能当清单过一遍：列出本次动作的「过程信号」与「终态实证」两栏，实证栏填满才宣成功。
